**核心发现:本轮没有证明"按需加载 Skill"优于无 Skill 基线。** 设计 §16.2
预先声明"不要求实验必须证明方案优于基线",以下是对该结果的诚实归因:

1. **任务太简单**:fixture 规模下五个工具 + 系统提示已含引用纪律,
   Skill 的增量方法(口径校验、修订检查)在系统提示与工具结构化错误里
   已部分内生;A 组模型也自然按"先取数后计算"行事。
2. **C 的两处失败是表达层而非方法层**:引用了 `docv-*`(文档版本 ID)
   而非 `chk-*`(证据 ID)——结果校验器应把 docv 视为合法证据引用并
   归一化;另一例完成了分析但未在文本中写出关键数值。
3. **单次运行 + 小样本**:n=9,随机性未控制(§16.2 要求关键样例重复
   运行,属下一轮);0.11 的完成率差异在 1 个样例的量级内。
4. **C-old 完胜 C(earnings 子集)**:0.1.0 的 Skill 更短,任务又简单——
   与"Skill 方法在难任务上才显增量"的假设一致,但不能据此发布回退
   (§16.4 门槛:需在更难、更多样的任务集上复验)。

## 2. 成本观察

- B(全装入)输入 token 比 C 低——反直觉,原因是 B 一次装入后不再
  read_file Skill 正文(每次读取都是一次工具往返与上下文增长);C 的
  按需加载在小 Skill 集上未体现成本优势,预期在 Skill 数量/体积增大后
  才显现,下一轮验证。
- D 零模型调用、零成本、P50=0——固定流程的价值在成本极低,代价是
  任务覆盖 3/9。
