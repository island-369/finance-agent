## 2. 原生恢复能否满足 M3 的结论

**结论:满足,但需要多个应用侧适配点,不能裸用。**

已验证(离线跨连接 + 真实模型跨进程):

- 中断:HumanInTheLoopMiddleware 在工具执行前暂停,状态 `waiting_approval`,
  预算中的工具计数为 0(中断先于执行)。
- 恢复:新进程/新连接以相同 `thread_id` 重建 Agent,`Command(resume={"decisions":[...]})`
  继续,对话历史来自检查点而非内存,最终结构化结果完整。

适配点(进入 M3 需求):

1. **应用侧计数不进检查点**:引擎检查点只保存图状态;预算计数、租约、fencing token
   属应用任务表(M3 的 `runs` 表)。恢复时预算目前从零计数,违背设计 §10.4
   "恢复沿用已消耗计数",是已登记的 M0 缺口。
2. **重建一致性**:恢复要求以相同 thread_id、兼容的图结构与工具集合重建 Agent。
   M3 需在 RunContext 固化引擎版本、适配器版本与工具版本(设计 §6.3 已列)并做兼容检查。
3. **恢复应答数量对齐**:并发工具调用时审批决定必须与挂起调用数逐位对应
   (真实模型实测;详见 §4 决策 3)。
4. **失败恢复的重试策略**:失败的恢复尝试可能污染线程(详见下方已知限制)。
   M3 的恢复程序需要"换新 thread 重跑"或清理逻辑,不能假定同 thread 重试幂等。

已知限制(如实记录,不视为已解决):

- 审批中断只覆盖工具调用边界;进程被强杀(kill -9)场景未在 M0 验证,
  M3 用 Worker 租约 + 检查点续跑验证。
- SQLite 检查点文件适合单 Worker;多 Worker 并发写同一文件不做声明。
- 工具结果超长时的外置存储(设计 §10.3 缓存、§9.4 引用化)未实现。
- **失败恢复会污染线程(真实模型实测)**:一次数量不匹配的恢复尝试失败后,
  同一 thread 上后续携带正确 payload 的恢复仍重放旧的错误应答
  (thread real-2 实测;新线程 real-3 立即成功)。机制推断为图引擎把上次
  resume 应答记录进了任务待写状态,但未在 M0 深入验证。M3 的重试策略必须
  考虑:恢复失败的任务应换新 thread 重跑,或先清理待写状态。

## 4. 关键实现决策(及理由)

1. **response_format 显式 ToolStrategy**:不用 AutoStrategy,避免策略依模型类型漂移;
   结构化结果以工具调用提交,离线脚本模型与真实模型走同一解析路径。
2. **DeepSeek 关闭思考模式**:引擎 ToolStrategy 对每次模型调用强制
   `tool_choice="any"`(langchain-openai 转为 `required`),DeepSeek 思考模式
   拒绝该值(HTTP 400)。通过 `extra_body={"thinking":{"type":"disabled"}}`
   关闭思考后原生机制即可工作;`FINANCE_AGENT_THINKING=enabled` 可重新打开
   (打开后当前引擎的结构化输出路径不可用,属于供应商能力边界而非本项目缺陷)。
3. **恢复 payload 与挂起调用数对齐**:真实模型会在一回合并行发起多个受审批
   门控的工具调用(实测 2 个),batched 模式的决定必须按位置一一对应;
   `build_resume_payload` 从检查点读取 `action_requests` 数量构造决定。
   离线脚本模型发现不了这个问题——单工具调用的脚本永远不会触发数量失配。
4. **只读 Skill 视图**:`FilesystemBackend(root_dir=视图目录)` 限定范围,
   `FilesystemPermission(operations=["write"], mode="deny")` 拒绝写入。
   仓库内版本化布局 `skills/<name>/<version>/` 由应用展开为扁平视图并生成
   内容哈希 manifest——设计 §7.3"注册表由 SKILL.md 解析生成"的雏形。
5. **预算语义**:"先计数、后检查"——越界的那次调用既已发出就如实计数
   (§10.4 尽力约束,不宣称精确封顶);工具侧另有执行前预检查,返回结构化
   `BUDGET_EXCEEDED` 错误而非异常,Agent 可降级为部分结论。
6. **时间边界在工具执行端**:`as_of` 由闭包注入任务截止时间;模型传入更晚的
   `as_of` 返回 `TIME_BOUNDARY_VIOLATION`,修订版本按截止时间内最新可得选择。
   真实运行中模型自发使用了早于截止时间的 `as_of` 探索修订前数据,行为符合约束。
7. **检查点序列化器显式注册类型**:`JsonPlusSerializer(allowed_msgpack_modules=[M0ResearchResult])`,
   消除"unregistered type"警告,保证跨进程恢复在未来版本不被默认拦截。
8. **公开事件最小化**:只映射模型/工具四类事件,附 usage 与输入摘要截断;
   不外发引擎内部 chain 事件,不依赖模型内部思维过程。
