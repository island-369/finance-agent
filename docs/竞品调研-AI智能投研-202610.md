# AI 智能投研:竞品与开源项目调研(2026-10)

> 用途:面试准备 + 自研金融Agent 项目对照。
> 信息来源:§2、§3 由联网调研 agent 实时检索整理(来源链接内嵌);§4 国际产品为模型知识整理、细节建议面试前核实;§5-§7 为综合分析。

## TL;DR

- **三类玩家、三种壁垒**:数据终端商(同花顺/Wind/东财/聚源)靠**数据闭环**,券商(华泰/招商/国泰海通/九方)靠**牌照与投顾服务**,大厂与初创(蚂蚁/阿里/AlphaSense/Hebbia)靠**基座模型与企业级 RAG**。数据闭环是最深的护城河。
- **架构高度趋同**:`通用基座(自研/闭源API/开源) + 金融语料继续预训练 + RAG 接研报/公告/财报/行情`,2025 年起普遍叠加**推理模型(DeepSeek-R1 类)+ Agent 化**(MCP、Skills、多智能体编排)。
- **开源收敛到同一套角色本体**:分析师(并行取数)→ 多空研究员辩论 → 交易员/组合经理 → 风险复核;**LangGraph 是事实标准**。
- **可靠性共识:"数字归代码,叙事归 LLM"**——强类型输出契约、确定性重算、来源可溯(provenance)、反思记忆。这与本项目的"结果校验链"方向完全一致,是面试中最值得展开的设计共识。

## 2. 国内商业产品(联网调研,截至 2026-10)

### 2.1 同花顺:问财 + HithinkGPT + iFinD
- **定位**:C 端为主。问财从选股问答升级为自研金融大模型驱动的投研/投顾平台,覆盖选股、策略生成、回测;iFinD 面向机构。
- **架构**:自研基座 HithinkGPT(2024.1 内测),万亿级金融预训练 tokens、每月新增数千亿(依托自有 HiFin 金融数据库),50+ 技能、多模态;AI PC 版用 3000 万行真实策略代码继续预训练。2025 年问财完成 Agent 化升级,并与阿里千问合作(千问的股票/财报数据反向来自同花顺)。
- **数据**:自有 HiFin 闭环,国内最强数据自给者之一。
- **动态**:2025 年报营收 60.29 亿(+44%)、净利 32.05 亿(+75.79%),AI 驱动明显。([内测公告](https://stock.10jqka.com.cn/20240102/c653710580.shtml)、[华尔街见闻](https://wallstreetcn.com/articles/3753925))

### 2.11 国内共性总结与趋势
1. **三类玩家、三种壁垒**:数据终端商靠数据闭环;券商靠牌照、投顾与分销;大厂靠基座模型与算力。数据闭环是最深护城河。
2. **架构高度趋同**:通用基座 + 万亿级金融语料继续预训练 + RAG 是标配;2025 年起普遍叠加推理模型 + Agent 化,关键词从 Chatbot 转向多智能体、MCP、Skills、工作流编排。B 端工具链比 C 端聊天更赚钱、落地更快。
3. **合规是硬约束**:生成式 AI 备案是入场券;《AI 生成合成内容标识办法》2025.3 发布、2025.9.1 施行(GB 45438-2025,显式+隐式标识);荐股需投顾牌照,2025 年 46 家投顾机构被罚 56 次,监管点名"AI 荐股"非法金融活动。典型合规工程化路径:蚂蚁的"持牌机构提供服务"、国泰海通的"大模型+小模型可信输出"。
4. **商业化信号**:同花顺营收 +44% 证明 AI+金融信息订阅模式跑通;券商从"降本"(Copilot)走向"增收"(AI 原生 App、买方投顾);开源金融模型(轩辕、九章生态)与闭源自研并行。

## 3. 开源项目(联网调研,截至 2026-10)

### 3.1 TauricResearch/TradingAgents ⭐ 115,676
多 Agent 交易决策框架(论文 arXiv:2412.20138),模拟交易公司分工:**四层流水线 + LangGraph 状态图**——①分析师团队(基本面/情绪/新闻/技术,4 角色并行调工具取数);②研究员团队(多/空研究员对分析师报告做多轮**结构化辩论**);③交易员汇总提案;④风险管理团队(多风险人格再辩论)+ 组合经理批准/否决。数据经 `dataflows/` 统一路由到 yfinance/FinnHub/SEC EDGAR/FRED/Reddit,做了 **point-in-time 防未来函数**处理。
- 技术栈:Python 3.11+、langgraph 1.x、多供应商 LLM registry、SQLite checkpoint、CLI(Typer/Rich)。
- **借鉴点**:多空辩论+经理裁决;反思记忆(对历史决策复盘提炼教训注入后续 prompt);point-in-time 数据契约防止回测偷看未来。

### 3.2 virattt/ai-hedge-fund ⭐ 64,270
教育/研究向 AI 对冲基金模拟(明确不实盘)。v2 引擎:`FUND = STRATEGY 组合 → MODEL = alpha 模型产出 Signal(conviction ∈ [-1,+1] + thesis)`。**裁量型 pod 由 LLM 投资人人格驱动**(Buffett/Munger/Graham/Lynch 等),**系统型 pod 是纯量化模型**,两类实现同一接口。执行层统一为 `advance()` 单动词:**回测与模拟盘走同一代码路径,逐字节可复现**;T 收盘决策 T+1 执行。
- **借鉴点**:基金→策略→模型的科层抽象与统一 Signal 接口;**哈希链账本**保证 track record 不可篡改;LLM 输出强类型契约层(与本项目"结果校验链"同构)。

### 3.3 AI4Finance-Foundation/FinGPT ⭐ 21,473
开源金融 LLM(LoRA 微调路线,对标 BloombergGPT:$300/次微调 vs $3M 全量训练)。核心是数据采集管道 + LoRA/RLHF + benchmark;情感分析用 RAG(检索相似历史样本再微调)。功能增量基本停在 2023-2024。
- **借鉴点**:"底座冻结 + 轻量适配"思想;自动数据策展管道保证语料保鲜。

### 3.4 AI4Finance-Foundation/FinRobot ⭐ 8,311
金融决策 Agent 平台(论文 arXiv:2405.14767),已转向生产级。同一域层叠三代实现:V0 AutoGen → V1 OpenAI Agents SDK → **V2 PydanticAI + FastAPI + React/Tauri 桌面投研工作站**。核心原则:**"models reason, software computes, agents orchestrate, systems verify"**——所有财务数字(DCF/DDM/LBO/WACC/comps/蒙特卡洛)由纯 Python 确定性算子计算并带 **provenance 追踪**,LLM 只负责推理、综合与叙述。工作流:数据 → 估值 → 辩论 → 综合 → 13 章"投委会式"研究报告(目标价+置信度+数据 caveats),全程可追溯。
- **借鉴点**:**确定性计算与 LLM 叙述严格分离**(最佳同构参考);全链路 provenance;"域层稳定、编排层可替换"的多代架构。

### 3.5 microsoft/qlib ⭐ 49,732 + microsoft/RD-Agent ⭐ 15,062
Qlib 是 AI 量化研究全流程平台(数据处理→因子→模型→回测→组合),配置驱动,内置 Alpha158/360 因子库与 point-in-time 数据,本身非 Agent 系统。RD-Agent 用 LLM Agent 自动化研发闭环:Research Agent 提出因子/模型假设 → Development Agent 写代码 → 回测(接 Qlib)→ 反馈迭代,**因子与模型交替共优化**;另有"读研报/论文→实现因子"的 Research Copilot;MLE-bench 榜单第一。
- **借鉴点**:"假设→实现→实验→反思"的演化循环;Agent 只产假设和代码,评估交给确定性回测引擎。

### 3.6 OpenBB ⭐ 74,744
"Open Data Platform"——数据工程基础设施层,宣称服务 analysts、quants 和 **AI agents**。核心是标准化数据接口:`obb.equity.price.historical("AAPL")`,供应商插件接入一次,多端消费——Python、REST API(FastAPI)、Excel、**MCP server(供 AI Agent 调用)**。Agent/前端独立仓库,商业闭源 Workspace 做企业 UI。
- **借鉴点**:**数据层与 Agent 层解耦**,"connect once, consume everywhere";面向 Agent 时代的数据平台形态 = 统一 REST + MCP。

### 3.7 论文配套代码:FinMem ⭐ 967 / FinAgent ⭐ 76
均已停更(2024-08)。FinMem:单 Agent 三模块(人格/分层记忆:工作-短期-长期、重要性驱动遗忘/决策)。FinAgent:多模态(价格图+新闻)双通道记忆 + 工具增强 + 反思。架构可参考,工程不可直接用。

### 3.8 深度研究 Agent:gpt-researcher ⭐ 30,305 / storm ⭐ 31,698
- **gpt-researcher**:planner + execution agents——规划 Agent 生成研究问题 → 并行执行 Agent 抓取 → 摘要溯源 → 上下文过滤 → Publisher 聚合成带引用报告;支持递归广度+深度研究、本地文档 RAG,Next.js 前端。
- **storm**(斯坦福,Wikipedia 式长文):预写阶段(检索 + **多视角提问**,模拟"写手 vs 专家"对话)+ 写作阶段;Co-STORM 增加专家/主持人圆桌与动态 mind map;基于 dspy;2025-09 后明显放缓。
- **借鉴点**:多视角提问提升覆盖面;大纲/引用前置的两段式生成;并行子任务+引用溯源是校验链的基础件。

### 3.9 补充:hsliuping/TradingAgents-CN ⭐ 32,538
原版之外最成功的中文衍生项目,面向 **A 股**:单股研究、自然语言选股(6000+ 股票筛选)、通用研究、AI 记忆、Skill 中心、纸面交易;数据源换 Tushare/AkShare,模型主推 DeepSeek/GLM/Qwen。技术栈:Python 3.11 + **FastAPI + Vue 3 + MongoDB/Redis**,完整 Web 前端;Apache-2.0 核心引擎 + 商业 Pro 的开源模式。
- **借鉴点**:本土化落地样本(A股数据源适配、中文报告、合规话术包装"研究辅助,不构成投资建议")。

### 3.10 开源生态共性总结
1. **角色分工趋同**:数据/基本面/情绪/新闻分析师 → 多空研究员辩论 → 交易员/组合经理 → 风险复核,几乎全部收敛到这套投研角色本体。
2. **编排框架**:LangGraph 是事实标准;微软系用自研演化循环;学术代码多为手写循环或 dspy。状态图 + checkpoint 断点续跑 + 并行分析师是当前最佳实践。
3. **LLM 接入**:普遍通过 LiteLLM/langchain 多供应商 registry(OpenAI/Anthropic/DeepSeek/Qwen/GLM),强调可换底座。前端从 CLI/TUI → Next.js → FastAPI+Vue/Tauri 桌面端演进;**对话式工作台是主流形态**。
4. **数据层独立于 Agent 层**:OpenBB 的 provider 抽象 + MCP、TradingAgents 的 dataflows/vendor 路由是范式;数据可信度靠 point-in-time、来源白名单、结构化输出契约保证。
5. **"数字归代码,叙事归 LLM"**:FinRobot 的确定性算子 + provenance、ai-hedge-fund 的哈希链账本与 LLM 契约、RD-Agent 的"Agent 提假设、回测引擎做裁判",共同指向同一原则——**LLM 不直接产出可信数字,校验链(强类型契约 + 确定性重算 + 来源可溯 + 反思复盘)才是可靠性所在**。

- **Bloomberg**:2023.3 发布 BloombergGPT 论文(50B 参数,363B tokens 金融语料 FinPile + 通用语料混合训练)——自研路线的标杆;此后更务实的路线是把 LLM 能力直接集成进终端(ASK BLOOMBERG、Company Lens、文档摘要等),企业级私有部署 + 自有数据闭环。
- **Morgan Stanley**:2023 起与 OpenAI 深度合作。AI @ Morgan Stanley Assistant:GPT-4 + RAG 检索内部研究知识库(约十万级研报/文档),服务 ~1.6 万财务顾问;**Debrief** 自动生成客户会议纪要与后续行动项。是"通用闭源模型 + 企业 RAG"而非自研模型的代表。
- **JPMorgan**:LLM Suite 覆盖 ~20 万员工(与 OpenAI 等合作构建,内部工具网关,可插换模型);IndexGPT 用 GPT-4 生成主题指数关键词。路线是"平台化网关 + 多场景小应用"。
- **AlphaSense**:企业级投研搜索/情报平台,Assistant 提供 AI 摘要与跨文档综合;语料含财报、电话会纪要、**专家通话库**(2024 年收购 Tegus 加固这一壁垒);微调模型 + Azure OpenAI。估值约 40 亿美元(2024)。对标国内"妙想投研助理/WarrenQ"。
- **S&P Global Kensho**:Kensho LLM Suite(面向金融行业的内部 LLM 平台)、Scribe(会议转录)、Benchmarks(金融 LLM 评测);与 Capital IQ 数据深度集成。
- **Robinhood Cortex**:2025 年发布的 C 端 AI 投资助手(Gold 订阅):摘要市场动态、解读个股异动、Trade Builder(自然语言→策略);新闻摘要部分与 Perplexity 合作(报道称)。"订阅制 AI 助手"形态,对标国内"AI涨乐"。
- **Perplexity Finance**:搜索 RAG 起家延伸的金融垂直:财报仪表盘、SEC 文件问答、实时行情资讯、选股筛选;强项是引用溯源与实时性。
- **OpenBB**:见 §3.6,开源核心 + 商业 Workspace(企业 AI 投研门户,支持自定义 agent 接入)。
- **Hebbia**:Matrix 产品——"agent 化的表格":对海量文档(纪要、财报、邮件)做 agentic 检索与分析,结果以表格呈现;在 PE/资管很受欢迎(2024 年 a16z 领投 ~1.3 亿美元融资)。"把 agent 藏进工作流"的代表。
- **Rogo**:面向投行/机构投资的 AI 分析师,融资与并购分析场景,主打金融专业 benchmark 上的表现。
- **TradingView**:2025 年推出 AI 分析师 Gene(个股/行情对话分析),依托其全球图表社区流量。

**国际共性**:① 自研基座(BloombergGPT)已被证明性价比低,主流转向"闭源/开源 API + 企业 RAG + 数据壁垒";② 面向机构的成功产品都重**工作流嵌入**(终端、表格、纪要)而非纯聊天;③ 企业级把**溯源、权限、合规**当一等公民;④ C 端靠订阅制 AI 助手变现。

## 5. 共性架构模式与技术栈(综合)

### 5.1 典型四层架构
```
┌─ 应用层:对话工作台 / 研究报告 / 图表 / 订阅推送 / 盯盘定时任务(SSE 流式)
├─ Agent 层:LangGraph 状态图编排;分析师并行 → 辩论 → 决策 → 风险复核;
│            reflection 记忆;deep research"检索-推理-再检索"循环
├─ 模型层:基座(自研 / 闭源 API / 开源微调)+ 金融语料继续预训练;
│          推理模型(DeepSeek-R1 类)做深度分析;模型路由降本(简单问题走小模型)
└─ 数据层:行情/财报/公告/新闻/研报(自有闭环 or Wind/Choice/iFinD/Tushare/AkShare/
           yfinance/FMP/SEC EDGAR);供应商抽象(OpenBB provider / MCP);point-in-time
```

### 5.2 关键工程决策(面试高频)
1. **自研模型 vs RAG**:自研金融大模型(同花顺/东财/轩辕/BloombergGPT)适合"有数据闭环 + 有算力"的玩家;其余普遍是"通用基座 + RAG + 少量微调(LoRA)"。面试说法:RAG 解决知识时效与溯源,微调解决风格与领域判断,推理模型解决复杂分析,三者互补。
2. **多 Agent 编排**:LangGraph 事实标准(状态图 + checkpoint + 并行节点);角色本体:分析师团队(并行取数)→ 多空辩论(对抗保证证据平衡)→ 交易员/组合经理 → 风险复核。辩论机制和反思记忆是 TradingAgents 证明有效的两大机制。
3. **金融 RAG 特殊处理**:财报/研报的表格与跨页解析、hybrid retrieval(BM25+向量)、rerank、股权/供应链 GraphRAG、**引用溯源**(每个结论可点回原文)、数字一致性校验。
4. **可靠性:"数字归代码,叙事归 LLM"**:强类型输出契约(pydantic)、确定性重算(DCF 等由代码算)、provenance 全链路可溯、审计日志。校验链是系统可靠性的核心,而非模型能力。
5. **合规工程化(国内)**:生成式 AI 备案;AI 生成内容显式+隐式标识(GB 45438-2025);投顾牌照边界;"研究辅助,不构成投资建议"话术;大模型+小模型/规则兜底的可信输出架构。
6. **评测**:金融评测集(FinEval、FinBen、InvestorBench)+ 离线回归 + 回测不偷看未来(point-in-time);RD-Agent 式"假设→实验→反思"演化循环。
7. **典型技术栈组合**:Python 3.11 + FastAPI + LangGraph + LiteLLM(多供应商)+ Postgres/pgvector + Redis + Langfuse/LangSmith 可观测;前端 Next.js/Vue3 聊天式工作台(@ant-design/x 同款思路);Docker 部署;定时任务做晨报/盯盘。

### 5.3 数据源对比(速查)
| 数据源 | 市场 | 特点 |
|---|---|---|
| Wind / Choice / iFinD | A股为主+全球 | 机构级、贵、全;东财妙想/同花顺即靠此类数据闭环 |
| Tushare / AkShare | A股 | 开源免费、够用但不保证质量,A股开源项目标配 |

## 6. 与本项目(金融Agent)的对照

本项目的已有设计(对话式工作台、多 agent 投研、结果校验链、审计、证据文本匹配、evals)与业界共识高度对齐,对照可讲的故事:

| 本项目已有 | 业界同构 | 差异化话术 |
|---|---|---|
| 结果校验链 | FinRobot"数字归代码"+ ai-hedge-fund LLM 契约 | 校验链是可靠性核心,业界共识 |
| 审计 / 证据匹配 | AlphaSense/企业级 provenance、合规要求 | 面向金融合规的溯源是 B 端刚需 |
| ChatGPT 式工作台(@ant-design/x) | TradingAgents-CN、FinRobot V2、OpenBB Workspace | 对话式工作台是开源主流形态 |
| evals 目录 | FinEval/InvestorBench、RD-Agent 演化评测 | 金融 agent 必须可评测 |

**可借鉴清单(按投入产出排序)**:
1. **多空辩论 + 经理裁决**(TradingAgents):成本低,显著提升结论证据平衡,面试最好讲。
2. **point-in-time 数据契约**:回测/历史研究不偷看未来数据——金融 agent 特有的可靠性问题,能体现领域理解。
3. **反思记忆**(对历史决策复盘,注入后续 prompt):区分 demo 与产品的关键。
4. **数据层 provider 抽象 + MCP**(OpenBB、恒生聚源 MCP 中台、华泰智研 MCP):"connect once, consume everywhere",2025-2026 业界明确趋势。
5. **哈希链账本**(ai-hedge-fund):track record 不可篡改,配合审计模块很自然。
6. **deep research 循环**(gpt-researcher 的规划-并行执行-引用聚合):报告生成质量的地板。

## 7. 面试视角:3-5 分钟架构讲述 + 可能被问的问题

**推荐讲述框架**:
1. 数据层:多源行情/财报/研报,provider 抽象,point-in-time;
2. Agent 层:LangGraph,分析师并行 → 多空辩论 → 决策 → 风险复核,反思记忆;
3. 可靠性:数字归代码、LLM 输出强类型契约、校验链重算、引用溯源、审计;
4. 合规:研究辅助定位、内容标识、免责声明;
5. 评测:离线评测集 + 回归,不偷看未来的回测。

**可能被问的问题**:
- 为什么用多 Agent 而不是单 Agent + 多工具?(证据平衡、职责隔离、可审计;但要承认开销)
- 如何控制幻觉?(工具取数替代生成、校验链重算数字、引用强制、拒答机制)
- 金融 RAG 和通用 RAG 的区别?(表格解析、数字一致性、时效分层、point-in-time)
- 自研模型还是用 API?(数据闭环才有意义;RAG+LoRA+推理模型互补)
- 合规红线怎么处理?(备案、标识、牌照边界、审计日志)
- 怎么评测投研 agent?(评测集 + 回归 + 回测协议;承认"预测质量"难测,先测流程可靠性)
